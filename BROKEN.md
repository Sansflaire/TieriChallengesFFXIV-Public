# BROKEN.md — Post-Mortem Index

**Read this before debugging anything, and before any commit / build / push.**

This file is an **index only**. One row per resolved issue: ID, one-line summary, keywords,
link to the detail file in [`Issues/`](Issues/). Details, attempts, and lessons live there.

**Tense: past.** Everything here is *fixed*. Active unresolved problems live in
[`KNOWN-ISSUES.md`](KNOWN-ISSUES.md).

**Analogy:** the clogged drain that burst a pipe. Fixed now — but never turn on the faucet
while the drain is clogged.

**This file grows, never shrinks.** When an entry's lesson stops being load-bearing, move its
detail file to `Issues/archive/` and move the row to the Archived table — don't delete it.

**Add an entry when** the bug (a) took more than one attempt, (b) could plausibly recur, or
(c) produced a non-obvious lesson. Add it in the *same commit* that ships the fix.

| 017 | **The D3D11 Test City renderer never drew a pixel, and the panel said `ACTIVE` in green the whole time.** THREE independent blockers plus a testing hazard, any one sufficient — which is why fixing one and seeing no change looked like fixing nothing. (1) `new BlendDescription { AlphaToCoverageEnable = false, IndependentBlendEnable = false }` never assigns `RenderTarget[0]`, and Vortice's struct has **no parameterless constructor**, so the initializer zeroed it — `RenderTargetWriteMask = ColorWriteEnable.None`. Colour writes were off. Zero is a **legal, silent** value: `CreateBlendState` succeeds, every draw "succeeds", nothing is written. **A zero-initialized graphics descriptor is not a defaults struct.** (2) The cbuffer declared `float4x4 ViewProj` unqualified; HLSL packs column-major, .NET `Matrix4x4` is row-major, so the shader computed `transpose(M)·v` — taking `clip.w`, and therefore the whole depth comparison, down with it. Both promoted from plausible to certain in minutes by **running the real initializer against the installed Vortice 3.8.2 and disassembling the real shader** (unqualified emits four `dp4`s against consecutive registers; `row_major` emits the mul/mad chain) — which replaced a whole planned probe ladder that never had to be built. Survived a release because `UsingDepthRenderer` was set from `Render()` returning true, i.e. from *submission*, and the panel rendered that as a claim about the screen: §4A question 2 failing in the field. **(3) The projection matrix had no depth term** (0.84.54.14): `Render.Camera` holds TWO projections — `ProjectionMatrix2` (+0x50) and `ProjectionMatrix` (+0x1A0) — and the feature shipped on +0x1A0, whose **third column is entirely zero**, forcing `clip.z == 0` for every vertex in the world. Under reverse-Z that is the far plane, failing BOTH our own `Greater` test against a buffer cleared to 0 AND the scene comparison. **Nearly invisible because everything else was provably right:** the trace projected the player to `px(1280.0, 706.3)` and Dalamud's `WorldToScreen` gave `px(1280.0, 706.3)` — pixel-exact — so X/Y/W were perfect and the city could never *look* wrong, only be absent. The fix is `Control.ViewProjectionMatrix` (+0x76B0), confirmed live. **And the reason it works is the keeper: FFXIV's projection is INFINITE-FAR REVERSE-Z, so its Z column is ALSO three zeros and `M43 = 0.1` — `clip.z` is a constant near plane and all depth rides in `clip.w`, giving `depth = 0.1 / distance`.** So `M43` is the load-bearing element, and the intuitive "check M13/M23/M33" test would reject the only matrix that works. **(4) The testing hazard:** two rounds of live results were void because `Build City` had not been pressed — `DrawWorld` returns on its first line when unbuilt, so no probe runs and "nothing on screen" is exactly what a broken renderer looks like. Compounded because the city is in-memory by design, so **every diagnostic build wiped it**, and the build state lived on a different tab from the switches. Fixes: explicit `RenderTarget[0]` with mask `All`; `row_major` **and no CPU transpose**; a live `CityMatrixSource` selector whose Auto rejects a provably depth-less matrix; telemetry that says `SUBMITTED` and admits nothing reads the finished surface; a loud NOT-BUILT banner repeated where results are read. | d3d11, blenddescription, rendertargetwritemask, colorwriteenable, zero initialized, descriptor, vortice, row_major, column major, matrix packing, hlsl, cbuffer, matrix4x4, transpose, dp4, disassembly, projectionmatrix, projectionmatrix2, rendercamera, control.viewprojectionmatrix, infinite far, reverse-z, m43, clip.z, clip.w, test city, blank, silent, active, submitted vs visible, unbuilt, probe control | 2026-09-12 | [017](Issues/017-zero-write-mask-and-column-major-matrix-blanked-the-d3d-city.md) |
